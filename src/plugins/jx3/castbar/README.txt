读条生成插件

通过 jx3/universe.py 按现有方式加载，不启动 HTTP 服务，不创建网页入口。
默认顺序：读条 职业 [名称] [时长] [正/倒] [小节] [尺寸]。
发送“读条”查看完整帮助；含空格的名称用双引号括起来。
可省略能识别类型的参数，用 - 或 _ 可明确跳过一个位置。
也支持全部使用 参数=值，或与简写混用。同一项的 参数=值 优先于位置参数。
职业也可写成 职业=长歌，方向=倒，时长=3；时间=.71 表示当前帧时间。
支持常见英文键：school、name、duration、direction、size、width、height、segments、format 等。
此前“职业 正/倒 时长”的简写仍兼容。

示例：
读条 长歌 徵 2.12 正
读条 七秀 回雪飘摇 3 倒 6 640x158
读条 七秀 回雪飘摇 3 倒 宽=640 小节=6
读条 长歌 徵 2.12 正 格式=png 时间=0.71 尺寸=640x158
读条 职业=长歌 名称=徵 时长=2.12 方向=倒 格式=apng
读条 长歌 徵 2 正 字体="Microsoft YaHei" 字号=15 粒子=关
读条 职业
读条 字体 黑体

支持 21 个职业及通用外观、正/倒读条、完整/部分动画、当前帧、技能名称、
时间文字、倒读条小节、尺寸、倍率、背景、帧率、粒子光效和字体。
仅保留读条素材，不包含曲风能量条。

PNG 保存当前时间的静态帧；GIF/APNG 默认保存 0 秒至总时长。
“范围=当前”保存 0 秒至“时间”的动画。
只填宽或高时，另一边按原素材比例计算；同时填宽高可拉伸。
默认使用项目已有的游戏原字体 src/assets/font/fzht.ttf（方正黑体_GBK），无需在系统安装。
“字体”指机器人部署主机已安装的字体；不会读取发指令者电脑上的字体，也不上传字体。
字体扫描兼容 Windows、Linux、macOS。Pillow/fontTools 已在项目依赖树中。

PNG/GIF 通过 OneBot 图片消息发送；APNG 通过 NapCat 群/私聊文件上传 API 发送，
保留原始动画与半透明度。适配器需要支持相应文件上传接口。
参考：https://napneko.github.io/onebot/api

渲染和编码在后台线程中执行。同一进程一次只生成一份图片，避免同时分配大量帧。
宽度 16–4096、高度 16–2048、时长 0.1–30 秒、最多 600 帧且总帧像素不超过 6400 万。
图片与 APNG 文件都以内存字节发送，插件不创建 exports/、日志或缓存文件。

光效使用从游戏 PSS 引用中解出的原始贴图，重建粒子移动、旋转和淡入淡出，
并包含左端头饰光晕。没有执行游戏原粒子引擎，不是逐帧精确还原。
素材源于本机游戏解包，归原作者所有；运行时不需要游戏或解包器。

静态资源按项目目录约定存放：
图片：src/assets/image/jx3/castbar/，按职业保留子目录。
配置与素材来源：src/assets/source/jx3/castbar/styles.json、font_source.json。
styles.json 中的 src 均相对于图片目录。
